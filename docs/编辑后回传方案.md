# 编辑后回传方案（设计稿，暂未实现）

> 状态：**方案设计，未排期**。
> 关联功能：打开文件（双击/右键“打开”，远程文件下载到本地缓存后用本地默认应用打开）。
> 本文描述在“打开”基础上实现“本地编辑 → 上传回远程”的完整方案。

------

## 1. 背景与目标

当前“打开”功能是**单向预览**：远程文件下载到本地缓存目录
`~/.cache/sftp-dual-pane/open/<远程路径>`，用本地默认应用打开。用户在本地编辑保存后，
改动**不会**同步回远程，容易产生“以为改了服务器文件，其实只是改了缓存副本”的误解。

目标行为：

1. 用户通过“打开”功能编辑某个远程文件的本地缓存副本并保存；
2. 应用检测到该缓存文件发生了修改；
3. 以非侵入方式提示“检测到修改，是否上传回远程？”；
4. 用户确认后自动上传覆盖远程原文件，并更新登记信息；拒绝则保留提示入口，稍后可再传。

------

## 2. 总体流程

```
打开远程文件
    │
    ├─ 下载到缓存副本（已有能力）
    ├─ 写入“打开登记表”：remotePath / localPath / 远程 mtime+size
    ├─ QFileSystemWatcher 监视 localPath
    ▼
本地编辑器保存
    │
    ├─ fileChanged 信号（800ms 防抖，编辑器常用“临时文件替换”式保存会连续触发）
    ├─ 校验文件仍存在（替换式保存会先消失再出现，需要重新 addPath）
    ▼
弹出上传确认（状态行提示 + 按钮入口）
    │
    ├─ 确认 → 冲突检测 → 上传覆盖 → 刷新登记表 → 远程面板 refresh()
    └─ 忽略 → 登记表标记 dirty，状态栏常驻入口可再次上传
```

------

## 3. 模块设计

### 3.1 打开登记表（新增 `OpenRegistry`）

- 存储位置：QSettings JSON（与连接配置同文件），键 `openRegistry`。
- 每条记录：

```json
{
  "localPath":  "/home/u/.cache/sftp-dual-pane/open/home/uos/Desktop/a.txt",
  "remotePath": "/home/uos/Desktop/a.txt",
  "remoteMtime": 1730000000,
  "remoteSize": 12345,
  "dirty": false
}
```

- 打开成功（`TransferThread::openReady`）时登记；应用退出不清理（下次打开同一文件可复用
  冲突检测基线）。缓存目录本身可在设置里加“清空预览缓存”入口。

### 3.2 文件监视（C++）

- `QFileSystemWatcher` 实例常驻；`openReady` 成功后 `addPath(localPath)`。
- 注意事项：
  - **替换式保存**：vim/VSCode 等保存时会删除重建文件，watcher 需在 `fileChanged` 后
    `removePath` + 文件重现后重新 `addPath`（轮询 `QFileInfo::exists` 或再挂一个 1s 单次定时器）；
  - **防抖**：800ms 内多次触发只报一次；
  - **忽略只读触发**：部分编辑器会 touch 文件（mtime 变了内容没变），比对 size + 内容短哈希
    （如前 4KB CRC32）过滤空变化；
  - watcher 上限（Linux inotify 默认 8192 个 watch），超出时提示并降级为“打开前提示未回传修改”。

### 3.3 冲突检测

上传前 `SftpClient::statFile(remotePath)` 取远程 mtime/size，与登记表比对：

| 情况                       | 行为                                   |
| -------------------------- | -------------------------------------- |
| 远程未变                   | 直接上传                               |
| 远程已变（他人/他端修改）  | 弹确认框：覆盖 / 本地另存 / 取消       |
| 远程文件已不存在           | 提示后按“新建上传”处理                 |

上传成功后回写登记表（新 mtime/size），并把 `dirty` 复位。

### 3.4 上传通道

- 复用 `TransferThread::enqueueUpload([localPath], remoteParentDir)`：
  `SftpClient::uploadFile` 已使用 `FXF_WRITE | FXF_CREAT | FXF_TRUNC`，天然覆盖语义；
- 目标目录 = remotePath 的父目录（`pathutil.h::joinRemotePath` 已有相关工具）；
- 进度条复用现有 `TransferProgress` 组件。

### 3.5 UI 呈现

- **状态行提示**：检测到修改时，底部状态行显示“⚠ a.txt 已在本地修改，可上传回远程”；
- **入口**：右上角（进度行附近）出现“上传修改(1)”小按钮，点击列出 dirty 文件并逐个/全部上传；
- **菜单**：右键菜单对“已打开过”的远程文件增加“上传本地修改”项（直接走冲突检测 → 上传）；
- 不做弹窗打断：编辑保存属高频动作，确认一律走状态行 + 按钮，仅“远程冲突”用模态框。

## 4. 边界与风险

| 风险                                   | 对策                                                     |
| -------------------------------------- | -------------------------------------------------------- |
| 二进制/大文件被误编辑后回传            | 打开时记录 MIME/大小；> 100MB 不登记回传（仍可预览）     |
| 断线时保存                             | dirty 保留，重连后状态栏入口仍可上传                     |
| 多个窗格/多连接打开同一远程文件        | 登记表以 remotePath 为主键，覆盖登记即可                 |
| 缓存副本被用户手动删除                 | watcher 触发时清理登记表                                 |
| 编辑器自动保存风暴                     | 防抖 + 内容哈希过滤                                      |
